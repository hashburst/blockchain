# HashBurst distribution gates

This file distinguishes implemented candidates from active network configuration.
It is not a declaration that mainnet is active.

## Deployment order

1. Pin the tested APoW executable and one future activation configuration across
   all four testnet validators and the observer. Run the dedicated APoW migration
   with existing recovery state and journals retained, not the EVM migration.
2. Start isolated work-signing miners before reaching activation. Verify actual
   work acceptance, BFT finalization, the beneficiary's exact 50-HBT reward once
   per block, no reward for rejected work, and continued EVM execution.
3. Compare fixed-height commitments on all five nodes and restart one validator;
   verify journal prefixes and convergence without restoring old journals.
4. Freeze the separate mainnet economic/identity/checkpoint manifests. Resolve
   the legacy migration and source-spendability policy before importing balances.
5. Provision mainnet observers, then validators and miners; repeat reward,
   finality, restart, native-transfer, EVM token and MetaMask tests. Publish
   endpoints and change dashboard mainnet state only after these gates pass.
6. Merge reviewed source and publish an immutable release with source SHA,
   binary checksums, platform tests and installation/rollback documentation.
   CI candidate artifacts do not constitute a production GitHub Release.

## Wallet integration contract

The wallet owns keys; the full node owns public state and transaction admission.
The offline signer never exposes a remote unlock/sign endpoint. The online side
must obtain chain ID, sequence/nonce, fee estimate, transaction hash and finalized
receipt. The signer must display network, account, recipient, amount, fee bound
and contract intent before authorization. HBT coin balances and token balances
must not be summed or substituted; native accounting uses 10^8 units per HBT,
whereas the existing EVM representation uses 10^18 wei per HBT.

Implemented: encrypted creation/import/unlock, native transfer draft preparation,
signing, explicit one-attempt submission and read-only receipt checking.
Pending: HBT-20/HBT-721 ABI interactions,
local desktop UI, Windows ACL-backed key custody and end-to-end user tests.
Keys are exported as encrypted keystores for self-custody, not uploaded to a
public dashboard. Existing founder/miner/validator keys must remain separate.

## Platform and hardware scope

Linux amd64/arm64 and macOS amd64/arm64 candidate builds are generated by CI.
Wallet tests run on Linux and macOS. Cross-compilation is not a hardware test.
The current node uses POSIX locking; Windows requires a separate locking and ACL
implementation and native tests. A Windows executable must not be advertised as
supported by disabling permission or lock checks.

Servers, HPC and VPS use the same node protocol, with measured resource limits
and dedicated service identities. The reference miner is CPU-only and uses the
HashBurst signed SHA-256 work format. There is no Stratum/pool adapter or GPU/ASIC
backend. Commodity Bitcoin ASICs cannot be assumed to accept this custom job
format. Device support must name the algorithm, firmware/protocol and actual
hardware test; mining another chain does not produce HashBurst APoW proofs.
